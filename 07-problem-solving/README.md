# 07 — Problem solving: algorithm, pseudocode, flowchart, debugging

## A simple problem-solving sequence
1. Understand the input and required output.
2. Work through one small example manually.
3. Write the algorithm as numbered steps.
4. Write pseudocode in plain language.
5. Draw a flowchart if it helps visualize decisions and loops.
6. Convert the logic into C.
7. Compile with warnings enabled.
8. Test normal, boundary, and invalid inputs.

## Common flowchart symbols
- Oval: Start / End
- Parallelogram: Input / Output
- Rectangle: Process / calculation
- Diamond: Decision
- Arrow: Flow direction

## Debugging checklist
- Read the first compiler error first.
- Check missing semicolons, braces, parentheses, and format specifiers.
- Check variable initialization.
- Trace loop start, condition, and update.
- Test zero, one, negative, and boundary values where relevant.
- Compile with `-Wall -Wextra -Wpedantic`.
